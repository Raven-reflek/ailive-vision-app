# AI直播-视觉采集APP

用手机摄像头对拍"直播手机的屏幕",在本机做文字识别(ML Kit),把识别出的弹幕文字上传云服务,作为 dycast 采集之外的**补充通道**
(不碰抖音服务器,从根上绕开协议层面的风险)。目前处于**真机测试阶段**。设计依据见大脑库 `docs/adr/0024-视觉OCR弹幕采集作为dycast补充通道.md`。

- Kotlin,minSdk 26,targetSdk 34,CameraX + ML Kit 中文文字识别,包名 `com.luxofilms.vision`。
- 与门店 APP 完全独立,只通过云服务按门店归并(同一家店可以同时有播放手机和采集手机两台设备)。

## 新同事先看

云服务仓库 `docs/交接与启动说明.md`(环境、构建、**签名注意事项**、发版流程)。

## 构建

```bat
:: 工程根目录先建 local.properties(已被 git 忽略),写(用正斜杠): sdk.dir=C:/Users/<你>/AppData/Local/Android/Sdk
.\gradlew.bat assembleDebug          :: app\build\outputs\apk\debug\app-debug.apk
.\gradlew.bat assembleRelease       :: app\build\outputs\apk\release\app-release.apk
```

每次发版同时改 `app/build.gradle.kts` 里的 `versionCode`(+1)和 `versionName`。发布走应用内更新通道:APK 命名 `vision-<版本>.apk`,
调云服务 `/admin/release` 登记时必须带 `"app":"vision"`。

**发布签名(0.5.2 起)**:`assembleRelease` 读工程根目录的 `keystore.properties`(已 gitignore,证书和口令由负责人保管、不在仓库里),格式:

```properties
storeFile=<证书文件的绝对路径,用正斜杠>
storePassword=...
keyAlias=vision
keyPassword=...
```

没有这个文件会退回 debug 签名,打出的包**装不上已装发布版的手机**;发版前用 `apksigner verify --print-certs <apk>` 核对证书指纹(见云服务 `docs/交接与启动说明.md` 的"签名"一节)。
0.5.1 及更早的版本是另一把 debug 签名,不能应用内更新到 0.5.2,要先卸载再装。证书丢了就只能让所有手机卸载重装,务必备份。

## 使用流程

1. 首次打开扫总部绑定二维码,绑定到测试门店(设备令牌加密保存)。
2. 点「标定」:两步标定(先框住被拍手机的屏幕四角,再框出弹幕滚动区域),标定数据以比例坐标保存。两步里都可以按住框的内部整体拖动(第一步形状和比例不变,拖到画面边缘整体一起停住);拖角点则改变形状。标定页左上角有返回首页的图标。
3. 点「开始采集」:前台服务按设定帧率取帧 → 透视纠正与裁剪 → 本地 OCR → **行合并 → 去重** → 上传文字。首页会显示最近识别到的弹幕(只记本次新上传的,同一条不会反复刷屏),用于核对识别效果。
   - **行合并**(`LineMerger`):一条弹幕太长在屏幕上折成两行,OCR 会给出两行,合回一条再上传。以文字特征为主:带"昵称:"前缀或"xx 来了"的行一定是新的一条;没有这些特征、上一行写满、行间距小,才并入上一条;拿不准不合并。上传时去掉"昵称:"前缀,只传内容。
   - **昵称与计时器前缀(0.5.6,ADR-0037)**:PK 倒计时、在线人数这类小部件常被 OCR 并进弹幕那一行(`15:00 小明:能洗车吗`、`00:55抖音用户,价格多少`)。上传前先剥掉行首的计时器 / 计数和匿名昵称"抖音用户"(含被读成 `, . ;` 或丢了的分隔符),**两边都是数字的冒号(时间 `15:00`、比分 `3:2`)不当昵称分隔符**;纯计时器行(`15:00`)直接丢。
     **刻意不做**:普通昵称后被读成逗号(`价格,多少钱`)分不清是不是正文逗号,不处理;`3:30到店可以吗` 这类开头就是正文里的时间,不剥。云服务也按同一规则兜底(旧版手机照样受益)。
   - **去重**(`DanmakuDeduper`):同一条弹幕会在画面上停留十几秒,每帧 OCR 的错字都不同。按字符相似度判重,最近 60 秒内见过就不再上传;贴着弹幕区上/下沿被切掉一截的条目,是已见过某条的一段就丢弃,否则连续出现 3 帧才放行。上传失败的不记账,下一帧重试。
   该区域是固定高度、区域内可滚动的(收起约 150dp,展开约 400dp 且不超过半屏),点标题行或右侧"展开/收起"切换;"清空"按钮清掉当前列表。条目最多保留 20 条,只存内存。
4. 现场确认标定准不准:首页"采集预览"(只读,左上角有返回按钮)。一张摄像头实时画面,叠着**屏幕框(橙)**和**弹幕区框(蓝,从正视图反算回原图,与实际识别的区域严格一致)**,
   屏幕框四个角标 1~4 用来判断顺序有没有标反;下面是最近一次识别出的文字,以及默认收起的"实际送去识别的画面"(展开后才会生成,用来判断字是否太小/太糊)。
   画面每秒约刷新 2 次(实测)。预览页**不自己开摄像头**(会和采集抢),所以只有采集运行时才有画面;页面禁止截屏/录屏、保持亮屏,画面只在内存里、不保存不上传;
   离开页面即停止出图,不影响识别和上传的节奏。
5. 服务有看门狗:摄像头长时间没有画面会自动重连并发告警;手机重启后会尝试自动恢复(后台启动相机在新版安卓上可能被系统限制,失败会发通知提示手动开始)。
6. **弹幕来源提示(0.5.4 起,2026-10-20,在 `kain/2026101903` 分支,未合并、未发布)**:每家店的弹幕来源(协议采集 / 视觉采集 / 两者都收,缺省两者都收)由店员在**助播 APP「我的」**里改、总部也能改并锁定,**本 APP 不提供设置入口**。
   来源设为"协议采集"时,云端不使用这台手机上传的弹幕(`/api/vision/text` 回 200 + `ignored:"source"`)。本 APP 此时在首页提示"这台上传的弹幕不会被使用",识别列表对应条目标"未使用"(不是"上传失败");
   **采集与上传节奏完全不变**,来源改回后下一次上传就恢复被使用。提示来自上传回包与首页回到前台时的 `/api/me`(`danmaku_source` 字段,老云服务没有 → 不提示)。决策见大脑库 ADR-0033,对接事项见 [`docs/服务端对接事项.md`](docs/服务端对接事项.md) S8。

7. **摄像头权限引导(0.5.5,2026-10-20 合入 main;0.5.5 当时记为未发布,与昵称拆分一起随 0.5.6 发出)**:摄像头是本 APP 的核心,权限没开采集一定起不来。
   - **点"开始采集"前先查权限**:没有就先弹系统授权窗口,不再让服务起不来后才报错。首页在"标定过但没有摄像头权限"时常驻一行红字提示。
   - **被拒不是死胡同**:第一次拒绝 → 弹窗"重新授权";选了"不再询问"(或第二次拒绝、策略禁用,系统不会再弹窗)→ 弹窗"去设置",直接跳本应用的系统设置页;
     从设置里开了权限回来,**自动接着开始采集**。标定页同样处理,取消会回首页(以前首次绑定后被拒会直接退出整个 APP)。
   - **采集起不来时告警按真实原因写**:摄像头权限被关(设置里撤销会让系统杀掉进程,服务随后被重启却起不来)→ "弹幕采集已停止:摄像头权限被关闭,点这里…按提示去系统设置里把相机改成允许";
     否则仍是"手机重启后弹幕采集没能自动恢复"(后台启动被系统限制)。以前两种情况都写成后一句。开机 / 升级后自启时先查权限,没有就直接发权限告警、不硬拉服务。
   - 授权窗口里建议店员选"使用应用时允许";选"仅这一次"可能让采集中途停止(**未验证**,弹窗里只写了"可能")。
   - 模拟器(Android 17 预览版,API 37)上验证过:首次拒绝、第二次拒绝/不再询问、去设置开启后自动开始采集、采集中撤销权限收到权限告警且不崩溃、标定页取消回首页;
     **开机自启路径(`BootReceiver` 先查权限)没在设备上验证**(shell 不能发受保护的开机广播),只有代码走读。

## 绑定失效与解除绑定

- 总部在管理台**撤销设备 / "换新手机"**后,这台设备的令牌作废。APP 会在两处发现:上传弹幕时服务端返回 401/410 + `need_bind`,
  以及首页每次回到前台时探测一次(`GET /api/me`,60 秒限频)。发现后**清除服务器/门店/令牌、停止采集、发通知、跳回绑定页并说明原因,标定数据保留**,
  重新扫码绑定后点"开始采集"即可,不用重新标定。
- 只有服务端明确返回 `need_bind` 才会解绑;网络错误、超时、5xx、限流都不会。**门店被停用(403)只提示、不解绑。**
- 首页底部有"解除绑定"按钮(标定保留)。0.5.3 起会先尽力调云服务 `POST /api/app/unbind`(5 秒超时)作废本设备令牌,总部设备列表里同步变成"已撤销";
  断网、接口未上线、令牌早已作废都照常解除本机,不会卡住。0.5.2 及更早版本只清本机,服务端令牌仍然有效。
- **设备类型**:0.5.3 起绑定时带 `device.kind = "vision"`,云服务据此区分采集手机与播放手机:总部"换新手机"默认只撤销播放手机,采集手机继续上传
  (勾选"同时撤销采集手机"才会一起撤)。更早版本绑定时没带 kind,云服务在它第一次上传时自动补标,不需要重新扫码。
- 服务端配合事项(设备类型区分、探测/解绑接口等)见 [`docs/服务端对接事项.md`](docs/服务端对接事项.md)。

| `CameraAlignActivity.kt` / `AlignOverlayView.kt` | 两步标定界面 |
| `CalibrationStore.kt` / `PerspectiveUtils.kt` | 标定数据与透视变换 |
| `Api.kt` / `Prefs.kt` | 云服务接口与加密存储 |

| `QuadMath.kt` / `AlignOverlayView.kt` | 标定框:点是否在框内、保持形状的整体平移(纯 Kotlin,可单元测试)/ 标定页的拖拽覆盖层 |

| `BindingGuard.kt` | 令牌失效判定(401/410+need_bind 才算)与失效后的统一善后(清绑定保留标定、停服务、告警) |

| `UpdateChecker.kt` | 应用内更新 |

## 已知限制

- 本地 OCR 对弹幕昵称识别很弱(昵称小、彩色、带打码),目前上传时昵称统一用固定值,只取弹幕内容。
- 标定弹幕区时**要避开弹窗、广告卡片、礼物特效、PK 倒计时等小部件,以及助播 APP / 总部大屏**:它们的文字会被当成弹幕,甚至和同一水平位置的弹幕混成一行;
  助播自己的回答和界面文案被拍回来还会被再答一遍(2026-10-22 真实直播测试踩到;云服务有 `echo` 回声过滤兜底,但源头避开最稳)。
- 行合并的阈值(`LineMerger`)按抖音游戏直播间的气泡式弹幕调出来的;别的直播间排版(行距/气泡样式不同、没有"昵称:"前缀)需要真机再核对,拿不准时倾向不合并(多问一次,不会拼错)。
- "xx 来了""开播地""欢迎来到直播间"这类系统提示,手机端仍会照常上传;服务端已实现丢弃/进场去名字(逐层开关、默认关,云服务合并并开启后生效,见 `docs/服务端对接事项.md` S7 与 ailive-brain ADR-0032),**手机端不用改**。
- 服务端对每台设备限流 40 次/60 秒,默认采样 0.5 帧/秒。
- 云端大模型识别路径(`/api/vision/frame`)已实现但受方舟账号权限问题阻塞,当前线上用的是本地 OCR 路径(`/api/vision/text`)。
