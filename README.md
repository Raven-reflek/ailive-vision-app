# AI直播-视觉采集APP

用手机摄像头对拍"直播手机的屏幕",在本机做文字识别(ML Kit),把识别出的弹幕文字上传云服务,作为 dycast 采集之外的**补充通道**
(不碰抖音服务器,从根上绕开协议层面的风险)。目前处于**真机测试阶段**。设计依据见大脑库 `docs/adr/0024-视觉OCR弹幕采集作为dycast补充通道.md`。

- Kotlin,minSdk 26,targetSdk 34,CameraX + ML Kit 中文文字识别,包名 `com.luxofilms.vision`。
- 与门店 APP 完全独立,只通过云服务按门店归并(同一家店可以同时有播放手机和采集手机两台设备)。

## 使用流程

1. 首次打开扫总部绑定二维码,绑定到测试门店(设备令牌加密保存)。
2. 点「标定」:两步标定(先框住被拍手机的屏幕四角,再框出弹幕滚动区域),标定数据以比例坐标保存。两步里都可以按住框的内部整体拖动(第一步形状和比例不变,拖到画面边缘整体一起停住);拖角点则改变形状。标定页左上角有返回首页的图标。
3. 点「开始采集」:前台服务按设定帧率取帧 → 透视纠正与裁剪 → 本地 OCR → **行合并 → 去重** → 上传文字。首页会显示最近识别到的弹幕(只记本次新上传的,同一条不会反复刷屏),用于核对识别效果。
   - **行合并**(`LineMerger`):一条弹幕太长在屏幕上折成两行,OCR 会给出两行,合回一条再上传。以文字特征为主:带"昵称:"前缀或"xx 来了"的行一定是新的一条;没有这些特征、上一行写满、行间距小,才并入上一条;拿不准不合并。上传时去掉"昵称:"前缀,只传内容。
   - **去重**(`DanmakuDeduper`):同一条弹幕会在画面上停留十几秒,每帧 OCR 的错字都不同。按字符相似度判重,最近 60 秒内见过就不再上传;贴着弹幕区上/下沿被切掉一截的条目,是已见过某条的一段就丢弃,否则连续出现 3 帧才放行。上传失败的不记账,下一帧重试。
   该区域是固定高度、区域内可滚动的(收起约 150dp,展开约 400dp 且不超过半屏),点标题行或右侧"展开/收起"切换;"清空"按钮清掉当前列表。条目最多保留 20 条,只存内存。
4. 现场确认标定准不准:首页"采集预览"(只读,左上角有返回按钮)。一张摄像头实时画面,叠着**屏幕框(橙)**和**弹幕区框(蓝,从正视图反算回原图,与实际识别的区域严格一致)**,
   屏幕框四个角标 1~4 用来判断顺序有没有标反;下面是最近一次识别出的文字,以及默认收起的"实际送去识别的画面"(展开后才会生成,用来判断字是否太小/太糊)。
   画面每秒约刷新 2 次(实测)。预览页**不自己开摄像头**(会和采集抢),所以只有采集运行时才有画面;页面禁止截屏/录屏、保持亮屏,画面只在内存里、不保存不上传;
   离开页面即停止出图,不影响识别和上传的节奏。
5. 服务有看门狗:摄像头长时间没有画面会自动重连并发告警;手机重启后会尝试自动恢复(后台启动相机在新版安卓上可能被系统限制,失败会发通知提示手动开始)。

## 绑定失效与解除绑定

- 总部在管理台**撤销设备 / "换新手机"**后,这台设备的令牌作废。APP 会在两处发现:上传弹幕时服务端返回 401/410 + `need_bind`,
  以及首页每次回到前台时探测一次(`GET /api/me`,60 秒限频)。发现后**清除服务器/门店/令牌、停止采集、发通知、跳回绑定页并说明原因,标定数据保留**,
  重新扫码绑定后点"开始采集"即可,不用重新标定。
- 只有服务端明确返回 `need_bind` 才会解绑;网络错误、超时、5xx、限流都不会。**门店被停用(403)只提示、不解绑。**
- 首页底部有"解除绑定"按钮(只清本机,标定保留)。
- 服务端配合事项(设备类型区分、探测/解绑接口等)见 [`docs/服务端对接事项.md`](docs/服务端对接事项.md)。

## 主要文件(`app/src/main/java/com/luxofilms/vision/`)

| 文件 | 职责 |
|---|---|
| `CaptureService.kt` | 前台服务:CameraX 取帧、节流、看门狗、状态通知 |
| `FrameProcessor.kt` | 透视纠正 + 裁剪 + 预处理 + 本地 OCR + 合并/去重 + 上传文字 |
| `LineMerger.kt` | OCR 视觉行 → 弹幕条:折行合并、去昵称前缀、标记贴边条目(纯 Kotlin,可单元测试) |
| `DanmakuDeduper.kt` | 客户端模糊去重 + 贴边半截条目处理(纯 Kotlin,可单元测试) |
| `CameraAlignActivity.kt` / `AlignOverlayView.kt` | 两步标定界面 |
| `CalibrationStore.kt` / `PerspectiveUtils.kt` | 标定数据与透视变换 |
| `Api.kt` / `Prefs.kt` | 云服务接口与加密存储 |
| `PreviewActivity.kt` / `PreviewBus.kt` | 采集预览页(只读)及其与采集服务之间的进程内信箱 |
| `QuadMath.kt` / `AlignOverlayView.kt` | 标定框:点是否在框内、保持形状的整体平移(纯 Kotlin,可单元测试)/ 标定页的拖拽覆盖层 |
| `PerspectiveMath.kt` | 纯 Kotlin 透视反算:把弹幕区(正视图矩形)映射回摄像头原图,供预览画框(可单元测试) |
| `FrameGate.kt` | 每帧做 OCR / 只出预览 / 丢弃的判定(OCR 节奏与 429 冷却不受预览影响) |
| `BindingGuard.kt` | 令牌失效判定(401/410+need_bind 才算)与失效后的统一善后(清绑定保留标定、停服务、告警) |
| `Alerts.kt` / `BootReceiver.kt` | 告警通知与开机自启 |
| `UpdateChecker.kt` | 应用内更新 |

## 已知限制

- 本地 OCR 对弹幕昵称识别很弱(昵称小、彩色、带打码),目前上传时昵称统一用固定值,只取弹幕内容。
- 标定弹幕区时**要避开弹窗、广告卡片和礼物特效**:它们的文字会被当成弹幕,甚至和同一水平位置的弹幕混成一行。
- 行合并的阈值(`LineMerger`)按抖音游戏直播间的气泡式弹幕调出来的;别的直播间排版(行距/气泡样式不同、没有"昵称:"前缀)需要真机再核对,拿不准时倾向不合并(多问一次,不会拼错)。
- "xx 来了""开播地""欢迎来到直播间"这类系统提示,手机端仍会照常上传;服务端已实现丢弃/进场去名字(逐层开关、默认关,云服务合并并开启后生效,见 `docs/服务端对接事项.md` S7 与 ailive-brain ADR-0032),**手机端不用改**。
- 服务端对每台设备限流 40 次/60 秒,默认采样 0.5 帧/秒。
- 云端大模型识别路径(`/api/vision/frame`)已实现但受方舟账号权限问题阻塞,当前线上用的是本地 OCR 路径(`/api/vision/text`)。
